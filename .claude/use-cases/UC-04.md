# UC-04: Refresh Token

| Field | Value |
|---|---|
| ID | UC-04 |
| Feature | AUTH-04 |
| Group | Authentication |
| Actor(s) | Customer, Staff, Admin |
| Data | Users |
| Business rules | [BR-03](../business-rules/BR-03.md), [BR-04](../business-rules/BR-04.md) |

## Description

The client obtains a new access token using a valid refresh token when the access token expires.

## Preconditions

- The user has a refresh token from UC-02 or a previous refresh.

## Main Flow

1. The client sends the refresh token.
2. The system finds the account holding this refresh token.
3. The system checks that the refresh token has not expired and the account is `Active`.
4. The system issues a new access token and a new refresh token, replacing the old refresh token (BR-04).
5. The client continues with the new tokens.

## Alternative Flows

- **A1. Invalid or expired refresh token**: At step 2 or 3, the system returns 401 Unauthorized; the user must log in again.
- **A2. Account locked**: At step 3, the system clears the refresh token and returns 401 Unauthorized.

## Postconditions

- The previous refresh token is no longer valid.
