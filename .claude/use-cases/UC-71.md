## Description

Staff review bank transfers that were not matched to an order automatically and resolve each one: apply it to an order, mark it refunded, or ignore it.

## Preconditions

- The user is signed in as Staff or Admin.
- At least one transfer in `PaymentTransactions` is not `Matched` and has no resolution.

## Main Flow

1. The user opens the list of transfers that need review, newest first.
2. The system shows each transfer: time, amount, transfer content, bank reference, match result and related order, if any.
3. The user chooses one action for a transfer:
   - **Apply to an order**: the user picks the order (e.g. the customer typed the order code wrongly). The system checks the order is `Online`, `Unpaid`, not `Canceled`, and its `TotalAmount` is at most the transfer amount, then sets the order `Paid`, `PaidAt` = transfer time, `TransactionCode` = bank reference (BR-34).
   - **Mark refunded**: after returning the money outside Daisy, the user marks the transfer `Refunded` with a note.
   - **Ignore**: the user marks the transfer `Ignored` with a note.
4. The system saves the resolution, the user and the time (BR-42).

## Alternative Flows

- **A1. Already resolved**: At step 3, the transfer has a resolution or is `Matched`; the system rejects the action.
- **A2. Order not payable**: At step 3 (apply), the order is COD, already paid, canceled, or its total is more than the transfer amount; the system rejects the action and the user refunds the transfer instead.

## Postconditions

- The transfer has a final resolution; if applied, the order is `Paid`.

## Related Use Cases

- UC-36 Receive Payment Webhook (creates the transfer records)
- UC-57 Update Payment Status
- UC-72 Expire Unpaid VietQR Order (late transfers for expired orders end up here)

## Notes

- A canceled order is never reopened by a late transfer; the transfer is refunded (BR-42).
