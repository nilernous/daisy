# UC-57: Update Payment Status

| Field | Value |
|---|---|

| Feature | AORD-05 |

| Data | Orders, PaymentTransactions |
| Business rules | [BR-07](../business-rules/BR-07.md), [BR-31](../business-rules/BR-31.md), [BR-32](../business-rules/BR-32.md), [BR-33](../business-rules/BR-33.md), [BR-34](../business-rules/BR-34.md), [BR-42](../business-rules/BR-42.md) |

## Description

Staff confirm COD collection, confirm a VietQR transfer manually, or mark a refund.

## Preconditions

- The user is signed in as Staff or Admin.

## Main Flow

1. The user opens an order and chooses a payment action.
2. **Confirm COD collected**: the system sets `Paid` and `PaidAt`.
3. **Confirm VietQR manually** (the webhook never arrived): the user enters the bank reference; the system checks it is not used by another order and not already recorded in `PaymentTransactions`, then sets `Paid`, `PaidAt` and `TransactionCode`.
4. **Mark refunded**: after refunding the customer outside the system, the user marks a `Paid` order as `Refunded`.
5. The system checks every change against the allowed transitions (BR-34).

## Alternative Flows

- **A1. Invalid transition**: At step 5, the system rejects the change.
- **A2. Reference already recorded**: At step 3, the transfer reached Daisy through the webhook but was not matched (e.g. wrong transfer content); the system rejects the action and the user resolves the transfer in UC-71 instead.

## Postconditions

- The order has the new payment status.
