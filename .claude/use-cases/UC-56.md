# UC-56: Cancel Order (Admin)

| Field | Value |
|---|---|
| ID | UC-56 |
| Feature | AORD-04 |
| Group | Order Management |
| Actor(s) | Admin, Staff |
| Data | Orders, ProductVariants, Products, Vouchers |
| Business rules | [BR-07](../business-rules/BR-07.md), [BR-35](../business-rules/BR-35.md), [BR-36](../business-rules/BR-36.md) |

## Description

Staff cancel an order with a reason; stock is restored.

## Preconditions

- The user is signed in as Staff or Admin.

## Main Flow

1. The user chooses Cancel order and enters a reason.
2. The system checks that the order is `Pending` or `Confirmed` (BR-36).
3. In one transaction, the system sets `Canceled`, `CancelReason` and `CanceledAt`, restores stock, and decreases `SoldCount` and the voucher's `UsedCount`.

## Alternative Flows

- **A1. Order shipping or completed**: At step 2, the system rejects the cancellation.
- **A2. Order already paid**: After step 3, the user refunds the customer and marks the payment `Refunded` (UC-57).

## Postconditions

- The order is `Canceled`; stock and counters are restored.

## Notes

- features.docx does not say whether staff can cancel a `Shipping` order (BR-36).
