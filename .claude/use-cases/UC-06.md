# UC-06: Reset Password

| Field | Value |
|---|---|
| ID | UC-06 |
| Feature | AUTH-06 |
| Group | Authentication |
| Actor(s) | Guest |
| Data | Users |
| Business rules | [BR-02](../business-rules/BR-02.md), [BR-05](../business-rules/BR-05.md) |

## Description

A guest sets a new password using the token from the reset email.

## Preconditions

- The guest has received a reset link (UC-05).

## Main Flow

1. The guest opens the reset link.
2. The guest enters a new password and confirmation.
3. The system checks that the token exists and has not expired.
4. The system hashes and saves the new password (BR-02).
5. The system clears the reset token and revokes the refresh token (BR-05).
6. The system confirms the reset and sends the guest to the login page.

## Alternative Flows

- **A1. Invalid or expired token**: At step 3, the system rejects the request and asks the guest to request a new link.
- **A2. Passwords do not match**: At step 2, the system shows an error.

## Postconditions

- The account has the new password; the reset token cannot be reused.
