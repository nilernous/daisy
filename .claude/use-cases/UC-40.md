# UC-40: Cancel Order (Customer)

| Field | Value |
|---|---|
| ID | UC-40 |
| Feature | ORD-04 |
| Group | My Orders |
| Actor(s) | Customer |
| Data | Orders, ProductVariants, Products, Vouchers |
| Business rules | [BR-08](../business-rules/BR-08.md), [BR-35](../business-rules/BR-35.md), [BR-36](../business-rules/BR-36.md) |

## Description

A customer cancels their own order while it is still Pending or Confirmed.

## Preconditions

- The customer is signed in and owns the order.

## Main Flow

1. The customer chooses Cancel order and enters a reason.
2. The system checks that the order is `Pending` or `Confirmed` (BR-36).
3. In one transaction, the system sets `Canceled`, `CancelReason` and `CanceledAt`, restores stock, and decreases `SoldCount` and the voucher's `UsedCount`.
4. The system confirms the cancellation.

## Alternative Flows

- **A1. Order already shipping or completed**: At step 2, the system rejects the cancellation.
- **A2. No reason given**: At step 1, the system asks for a reason.
- **A3. Order already paid**: At step 3, the order is canceled; staff refund the customer and mark it `Refunded` (UC-57).

## Postconditions

- The order is `Canceled`; stock and counters are restored.
