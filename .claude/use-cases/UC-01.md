# UC-01: Register

| Field | Value |
|---|---|
| ID | UC-01 |
| Feature | AUTH-01 |
| Group | Authentication |
| Actor(s) | Guest |
| Data | Users |
| Business rules | [BR-01](../business-rules/BR-01.md), [BR-02](../business-rules/BR-02.md), [BR-07](../business-rules/BR-07.md) |

## Description

A guest creates a customer account with full name, email and password.

## Preconditions

- The guest is not signed in.

## Main Flow

1. The guest opens the registration form.
2. The guest enters full name, email, password and password confirmation.
3. The system validates the input (required fields, email format, passwords match).
4. The system checks that the email is not already registered (BR-01).
5. The system hashes the password (BR-02) and creates the account with role `Customer` and status `Active`.
6. The system confirms the registration and sends the guest to the login page.

## Alternative Flows

- **A1. Invalid input**: At step 3, the system shows the field errors and creates nothing.
- **A2. Email already registered**: At step 4, the system rejects the registration with an 'email already in use' message.

## Postconditions

- A new `Users` row exists with `Role = Customer` and `Status = Active`.
