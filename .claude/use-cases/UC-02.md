# UC-02: Login

## Description

A guest signs in with email and password and receives an access token and a refresh token.

## Preconditions

- The guest has an account.

## Main Flow

1. The guest enters email and password.
2. The system finds the account by email.
3. The system verifies the password against the stored hash (BR-02).
4. The system checks that the account is `Active` (BR-03).
5. The system issues a JWT access token (with the user's role) and a refresh token, and stores the refresh token and its expiry (BR-04).
6. The system merges the guest's session cart into the user's cart (UC-31).
7. The user is signed in.

## Alternative Flows

- **A1. Wrong email or password**: At step 2 or 3, the system shows a generic 'invalid email or password' message without revealing which one is wrong.
- **A2. Account locked**: At step 4, the system rejects the login with an 'account locked' message.

## Postconditions

- A new refresh token is stored; any previous refresh token is replaced.
