# UC-72: Expire Unpaid VietQR Order

| Field | Value |
|---|---|
| ID | UC-72 |
| Feature | CHK-08 |
| Group | Checkout & Payment |
| Actor(s) | System |
| Data | Orders, OrderItems, ProductVariants, Products, Vouchers |
| Business rules | [BR-35](../business-rules/BR-35.md), [BR-36](../business-rules/BR-36.md), [BR-41](../business-rules/BR-41.md) |

## Description

A background job cancels VietQR orders that were not paid before their payment deadline and releases their stock.

## Preconditions

- A VietQR order is `Unpaid` and `Pending`, and `PaymentExpiresAt` + grace period has passed (BR-41).

## Main Flow

1. Every minute, the job loads the expired orders.
2. For each order, in one transaction, the system sets `OrderStatus = Canceled`, `CancelReason = 'Payment not received in time'` and `CanceledAt`, only if the order is still `Unpaid` and `Pending`.
3. The system restores the stock of each item, decreases `SoldCount`, and decreases the voucher's `UsedCount` if a voucher was used (BR-36).
4. The system commits the transaction.

## Alternative Flows

- **A1. Paid in the meantime**: At step 2, a webhook has just marked the order `Paid`; the conditional update changes nothing and the order is skipped.
- **A2. Error on one order**: At step 2-4, the transaction for that order is rolled back and logged; the job continues with the next order and retries on its next run.

## Postconditions

- The order is `Canceled` and its stock is available again.

## Related Use Cases

- UC-35 Pay with VietQR
- UC-71 Reconcile Payment Transactions (transfers that arrive after the order expired)

## Notes

- The customer sees the order as canceled in Order Detail (UC-38) and can place a new order.
