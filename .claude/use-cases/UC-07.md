# UC-07: Change Password

| Field | Value |
|---|---|
| ID | UC-07 |
| Feature | AUTH-07 |
| Group | Authentication |
| Actor(s) | Customer, Staff, Admin |
| Data | Users |
| Business rules | [BR-02](../business-rules/BR-02.md), [BR-06](../business-rules/BR-06.md) |

## Description

A signed-in user changes their password after confirming the current one.

## Preconditions

- The user is signed in.

## Main Flow

1. The user enters the current password, a new password and confirmation.
2. The system verifies the current password (BR-06).
3. The system hashes and saves the new password (BR-02) and updates `UpdatedAt`.
4. The system confirms the change.

## Alternative Flows

- **A1. Wrong current password**: At step 2, the system rejects the change.
- **A2. Passwords do not match**: At step 1, the system shows an error.

## Postconditions

- The account has the new password.
