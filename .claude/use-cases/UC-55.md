# UC-55: Update Order Status

| Field | Value |
|---|---|
| ID | UC-55 |
| Feature | AORD-03 |
| Group | Order Management |
| Actor(s) | Admin, Staff |
| Data | Orders |
| Business rules | [BR-07](../business-rules/BR-07.md), [BR-35](../business-rules/BR-35.md), [BR-41](../business-rules/BR-41.md) |

## Description

Staff move an order forward: Confirmed -> Shipping -> Completed.

## Preconditions

- The user is signed in as Staff or Admin.

## Main Flow

1. The user chooses the next status of an order.
2. The system checks that the move is allowed (BR-35).
3. The system saves the new status; moving to `Completed` sets `CompletedAt`.

## Alternative Flows

- **A1. Invalid move**: At step 2, the system rejects skipping a step, going backwards, or changing a `Completed` / `Canceled` order.
- **A2. Unpaid VietQR order**: At step 2, the system rejects confirming a VietQR order that is not `Paid` yet (BR-35).

## Postconditions

- The order has the new status.
