# UC-36: Receive Payment Webhook

| Field | Value |
|---|---|
| ID | UC-36 |
| Feature | CHK-06 |
| Group | Checkout & Payment |
| Actor(s) | Bank webhook service (System) |
| Data | Orders, PaymentTransactions |
| Business rules | [BR-32](../business-rules/BR-32.md), [BR-33](../business-rules/BR-33.md), [BR-34](../business-rules/BR-34.md), [BR-42](../business-rules/BR-42.md) |

## Description

The bank webhook service notifies Daisy of an incoming transfer, and Daisy marks the matching order as paid.

## Preconditions

- A VietQR order is `Unpaid`.
- The webhook service is configured with Daisy's webhook URL and key.

## Main Flow

1. The webhook service sends the transaction: amount, transfer content, bank reference and time.
2. The system verifies the webhook's API key or signature (BR-33).
3. The system checks that the bank reference is not already recorded in `PaymentTransactions` (BR-33).
4. The system extracts the `OrderCode` from the transfer content and finds the order.
5. The system checks that the order is `Online`, `Unpaid`, not `Canceled`, and that the amount is at least `TotalAmount` (BR-32).
6. In one transaction, the system records the transfer with `MatchResult = Matched` (BR-42) and sets `PaymentStatus = Paid`, `PaidAt` and `TransactionCode` (BR-34).
7. The system acknowledges the webhook.

## Alternative Flows

- **A1. Verification fails**: At step 2, the system returns 401 Unauthorized and changes nothing.
- **A2. Already processed**: At step 3, the system acknowledges the webhook without changes.
- **A3. No matching order, order not payable, or amount too low**: At step 4 or 5, the system records the transfer with `MatchResult` `NoOrder`, `OrderNotPayable` or `Underpaid` (BR-42), leaves the order unchanged, and acknowledges the webhook. Staff resolve it in UC-71.
- **A4. Order expired at the same moment**: At step 6, the expiry job (UC-72) has just canceled the order; the conditional update fails and the transfer is recorded as `OrderNotPayable`.

## Postconditions

- The transfer is recorded in `PaymentTransactions`; the order is `Paid`, or the transfer waits for staff (UC-71).

## Notes

- The webhook never changes stock, `SoldCount` or voucher usage (BR-33).
