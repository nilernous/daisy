# BR-41: VietQR Payment Deadline

| Field | Value |
|---|---|
| ID | BR-41 |
| Category | Checkout & Payment |
| Enforced by | Application (background job) + Database (`Orders.PaymentExpiresAt`, `CK_Orders_PaymentExpiresAt`) |
| Source feature(s) | CHK-05, CHK-08 |
| Used by | [UC-35](../use-cases/UC-35.md), [UC-38](../use-cases/UC-38.md), [UC-55](../use-cases/UC-55.md), [UC-72](../use-cases/UC-72.md) |

## Rule

A VietQR order must be paid before its payment deadline. An order that is still unpaid after the deadline and a grace period is canceled automatically and its stock is released.

## Details

- When a VietQR order is placed, `PaymentExpiresAt` = order time + `VietQr:PaymentTimeoutMinutes` (default 30 minutes). COD orders have no deadline (`PaymentExpiresAt` is NULL).
- The customer sees the deadline next to the QR code. After the deadline, the QR code is no longer shown.
- A grace period after the deadline (`VietQr:ExpiryGraceMinutes`, default 5 minutes) still accepts transfers, because bank webhooks can arrive late.
- A background job runs every minute and cancels orders that are `Online`, `Unpaid` and `Pending` and whose `PaymentExpiresAt` + grace period has passed.
- Canceling follows BR-36 in one transaction: `OrderStatus = Canceled`, `CancelReason = 'Payment not received in time'`, `CanceledAt`, stock restored, `SoldCount` and voucher `UsedCount` decreased.
- The cancel uses a conditional update (`WHERE PaymentStatus = 'Unpaid' AND OrderStatus = 'Pending'`), so it never cancels an order a webhook has just marked `Paid` (BR-33). The job is safe to run on several API instances at once.
- A transfer that arrives after the order was canceled is recorded with `MatchResult = OrderNotPayable` (BR-42) and staff refund it (UC-71).
