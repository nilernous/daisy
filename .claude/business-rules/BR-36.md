# BR-36: Order Cancellation

| Field | Value |
|---|---|
| ID | BR-36 |
| Category | Orders |
| Enforced by | Application |
| Source feature(s) | ORD-04, AORD-04 |
| Used by | [UC-40](../use-cases/UC-40.md), [UC-56](../use-cases/UC-56.md), [UC-72](../use-cases/UC-72.md) |

## Rule

An order can be canceled only while it is `Pending` or `Confirmed`, and a reason is required.

## Details

- Canceling sets `OrderStatus = Canceled`, `CancelReason` and `CanceledAt`.
- An order is canceled by the customer (UC-40), by staff (UC-56), or by the system when a VietQR payment deadline passes (UC-72, BR-41); the system uses the reason `Payment not received in time`.
- In the same transaction, stock is restored, `SoldCount` is decreased and the voucher's `UsedCount` is decreased.
- If the order was already `Paid`, staff refund the customer and set `PaymentStatus = Refunded` (UC-57).

## Notes

- features.docx does not cover canceling a `Shipping` order (e.g. failed delivery).
