# BR-42: Payment Transaction Record

| Field | Value |
|---|---|
| ID | BR-42 |
| Category | Checkout & Payment |
| Enforced by | Database (`PaymentTransactions`, `UQ_PaymentTransactions_BankReference`, `CK_PaymentTransactions_*`) + Application |
| Source feature(s) | CHK-06, AORD-05 (reconciliation not defined in features.docx; design decision) |
| Used by | [UC-36](../use-cases/UC-36.md), [UC-57](../use-cases/UC-57.md), [UC-71](../use-cases/UC-71.md) |

## Rule

Every verified incoming bank transfer is stored in `PaymentTransactions`, whether or not it matched an order. Transfers that did not match stay open until staff resolve them.

## Details

- Stored data: bank reference (unique), provider, receiving account, amount, transfer content, transfer time, time received, and the related order if one was found.
- `MatchResult` records the automatic outcome:
  - `Matched` — the order was marked `Paid` (BR-32).
  - `NoOrder` — no `OrderCode` in the content, or the code does not exist.
  - `Underpaid` — the amount is less than the order's `TotalAmount`.
  - `OrderNotPayable` — the order is already `Paid`, `Canceled` (including expired, BR-41) or COD.
- A transfer that is not `Matched` and has no `Resolution` needs staff review.
- Staff resolve it once, with one of:
  - `Applied` — the transfer is applied to an `Online`, `Unpaid`, non-canceled order whose `TotalAmount` is at most the transfer amount; the order becomes `Paid` with `TransactionCode` = bank reference.
  - `Refunded` — the money was returned to the sender outside Daisy.
  - `Ignored` — no action needed (e.g. a test or internal transfer).
- A resolution records who resolved it, when, and an optional note. It cannot be changed afterwards.
- A canceled order is never reopened by a late transfer; the transfer is refunded.
- Staff confirming a transfer manually on an order (UC-57) cannot use a bank reference that is already recorded here; they resolve that transaction instead (UC-71).
